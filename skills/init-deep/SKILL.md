# init-deep

基于当前项目的真实实现生成分层 AGENTS.md：根目录提供全局导航，子目录只描述局部差异。不要为每个目录生成文件，也不要把通用编程建议写成项目知识。

本 skill 是对 oh-my-openagent `init-deep` 的修改版，已适配 Codex 的工具、协作与保留既有约定的写入方式。来源、固定版本和差异见 [upstream.md](references/upstream.md)；上游许可见 [LICENSE.md](LICENSE.md)。

## 调用与范围

```text
$init-deep                       # 默认 update：最小更新现有文件，按需新增
$init-deep --create-new          # 读取既有约定后重建所选文件
$init-deep --max-depth=2         # 生成位置相对根目录的最大深度，默认 3
```

以上是任务选项，不是 CLI 命令。根目录深度为 0；深度限制约束写入位置，不限制核实相关实现。负数或非整数深度需澄清。以用户指定目录为范围，否则以当前工作目录所在仓库的根目录为范围；非 Git 项目使用当前目录。

仅调查和修改目标范围内的 AGENTS.md。README、源码、配置、角色、安装状态和检索索引不因本 skill 自动改变。用户若只要求分析、预览或建议，停在位置决策和拟议内容。

`--create-new` 表示重新组织内容，不代表丢弃用户规则、批量删除文件或覆盖无关修改。先完成调查和新稿，再逐文件替换；未选中的既有文件保留，过时文件列为候选清理项。只有用户明确要求清理时才删除已核对的目标文件。

## 1. 调查与证据

使用可用的计划工具跟踪调查、位置决策、生成、核验；无此工具时用简短进展说明。不依赖特定的 TodoWrite、task、background_output 或插件 API。

1. 确定目标根目录；记录 Git HEAD、分支、dirty 状态（非 Git 项目标明不适用）。区分既有用户改动与本次修改。
2. 读取适用于目标的祖先指导及范围内既有 AGENTS.md；CLAUDE.md 等文件只作为补充证据，不修改或机械复制。保留手写约定、受管理区块和有效的局部规则。规则与实现冲突时说明冲突，不静默改写规则；记录无法读取的指导文件并暂停对受影响范围的写入。
3. 按本项目的检索约定定位证据。已有 CodeGraph 索引且工具可用时优先使用；语义检索在可用时帮助定位，再聚焦读取。缺少工具或索引时直接使用文件列表、rg 和源码读取，不为本任务创建持久索引。
4. 调查实际目录职责、入口及调用链、模块边界、共享依赖、测试布局、构建/运行命令和 CI。参考清单、配置、命令实现及相关测试；目录名、框架惯例或旧文档不足以证明事实。
5. 可用时使用 LSP 的符号/引用与 ast-grep 的结构查询补充代码图谱。已覆盖证据不重复检索；缺少这些工具不阻塞，引用中心性等无法测量的项标为未知，不能猜测数值。

文件清单应包含相关的未跟踪文件及 `.github/` 等隐藏配置，排除 `.git/`、依赖、缓存、构建产物、生成代码和二进制等噪声。忽略规则与显式任务范围冲突时，以任务为准；不跟随目录符号链接越出目标范围，子模块或嵌套仓库默认只记录边界，除非用户明确纳入。

保持一个简短证据表：`事实 → 文件/符号/配置 → 适用目录 → 已确认或未知`。命令可从配置核实，未实际运行就不能写成“验证通过”。

### 按需委派

大型项目中，独立包、入口链路或测试/构建调查可并行分给只读 explorer；简单项目由主智能体直接完成。以独立证据缺口和当前并发能力决定数量，不按文件数无限扩增，也不为寻找某个文件启动智能体。

委派明确根目录、范围、现有约束和交付：职责/入口、局部约定、引用证据、未知项、是否值得建立子级指导。使用当前环境可用的角色或通用子智能体，不假设安装了本仓库角色。主智能体合并证据并决定位置。

## 2. 目录评分与位置决策

根目录始终纳入写入计划（只读模式仅提出计划）。对候选目录计算以下启发式分数，每项满足加权值，不满足为 0，无法测量标为未知，不参与计分：

| 因素 | 加分条件 | 权重 |
| --- | --- | --- |
| 文件量 | 目录直接包含的维护文件 >20 | 3 |
| 子目录量 | 直接子目录 >5，排除噪声 | 2 |
| 代码比例 | 直接维护文件中源码 >70%，分母为 0 时不计 | 2 |
| 独有约定 | 有适用于该目录的配置或工作流程差异 | 1 |
| 模块边界 | 从包清单、构建目标或入口调用确认独立模块 | 2 |
| 符号密度 | 直接源码中的已测量符号 >30 | 2 |
| 导出数量 | 直接源码中已测量导出 >10 | 2 |
| 引用中心性 | 目录对外接口的已测量引用 >20 | 3 |

分数 >15 优先建立子级；8–15 且有独立领域时考虑建立；<8 通常由父级覆盖。分数只用于排序：若没有父级之外的可执行指导，即使高分也不新增；独立包有关键局部约束时，低分也可新增并说明理由。未知项多时依据已确认边界与差异决定，不能用缺失分数推出“没有复杂度”。

输出位置表：`路径、已知分数、未知项、创建/更新/保留、理由`。限定在 max-depth 内；避免父子分数重复累加整个子树，也避免机械依赖 index.ts 或 __init__.py 推断领域。

## 3. 生成

先生成根目录，再生成子目录。多智能体写入时每个文件指定单一写入者，提供已确定的父级规则与局部证据；父级规则未确定时不并行写子级。

写入前再次读取目标文件并核对调查时的内容，合并期间新增的用户改动。已有文件优先局部 patch；重建模式也保留有效手写规则与管理区块。不覆盖符号链接指向的外部文件。新文件仅在所选路径不存在时创建。

### 根目录

按项目需要选择以下内容，不强制填满模板：

- 概览：项目目的、真实技术栈和明确工程边界。
- 结构：只展示有导航价值的目录和非显然职责。
- 任务导航：任务 → 位置 → 注意事项。
- 代码图谱：关键入口/符号 → 位置 → 作用；引用数只在实际测量时列出。
- 项目约定与禁止项：由已有规则、配置或实现证实的特殊约束。
- 常用命令：准确的工作目录、命令和必要前提；区分静态核实与执行结果。
- 易错点：生成代码边界、外部服务前提或项目特有陷阱。

通常控制在 50–150 行；小项目更短即可，保留必要用户规则不受硬行数限制。省略无内容的章节，不填占位符。不默认加入时间戳、分支或 SHA 等易过期字段；若项目已有该约定，使用本次实际值并标注 dirty 快照。

### 子目录

通常 30–80 行，只写局部职责、任务入口、不同于父级的约定与禁止项。父级规则按层级适用，无需整段复制；路径明确相对于本文件或根目录。没有足够局部内容就不创建。

用项目既有文档语言和可直接执行的短句。不要把研究过程、未证实猜测、凭证或临时私人上下文写入指导文件。

## 4. 核验与交付

逐个回读生成结果，核对路径、符号、目录职责、命令及前提与当前证据一致；移除父子重复、通用建议和虚构工具。检查原有有效规则、管理区块和用户 dirty 改动是否保留。

检查仅授权文件发生变化；Git 项目运行 `git diff --check`，并单独查看新增/未跟踪文件，因为默认 diff 不包含它们。文档任务无需自动跑全量产品测试；若实际运行命令，用隔离配置并准确报告结果。

最终报告模式、根目录、创建/更新/保留文件、子级位置选择理由和验证限制。区分“文件已生成”“内容已核实”和“实际运行验证”；目录数、行数只在实际统计时报告。
