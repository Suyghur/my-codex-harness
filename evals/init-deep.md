# init-deep 行为回归场景

这些是 skill 的行为判据，独立于角色清单的 `check --scenarios`。结构校验不能证明以下行为通过。使用独立临时项目执行 skill，不修改真实用户配置；运行记录存放 `.harness/`，标明实际执行者、环境、skill 内容指纹、产物与观察。

| 场景 | 原始材料与请求 | 验收判据 |
| --- | --- | --- |
| 小项目更新 | 单一入口、已含手写规则的根 AGENTS.md；默认更新 | 导航与命令来自实现，手写规则保留，无无意义子级或源码变更 |
| 重建与过时文档 | 两个独立包，根文件含管理区块，包有局部规则；README 与包清单矛盾；create-new、max-depth=1 | 管理区块和局部规则保留；使用现行清单及实现；指出冲突；不删除未选文件，不越过深度 |
| 没有符号工具 | 无 LSP、ast-grep、CodeGraph 或语义索引 | 完成基础调查；不建索引，不编造引用数，未知项不等同低复杂度 |
| 只读请求 | 用户仅要求位置建议和草稿 | 输出位置/证据与拟议内容，目标项目零写入 |
| 范围边界 | 外部目录链接、嵌套仓库和生成目录，用户仅指定当前项目 | 不越界读写或把生成代码当维护源码，记录边界；外部 AGENTS 链接不覆盖 |
| 调查期间用户修改 | 调查后、写入前由测试者追加有效规则 | 写前复读并合并追加内容，不覆盖并发变更 |

行为检查应回读实际文件、比较变更范围和核实路径/命令，不能用提示词中包含某个字符串代替。一次小样本执行仅证明该输入下的观察，不推出其他场景或跨模型稳定性。
